Платформенный слой — одна машина за интерфейсом#

Всё выше по течению — зрение, планировщик, управление — говорит физикой: кривизна, угол колеса, момент в cNm. Никто из них не знает, что машина — Volkswagen. Это знание живёт ровно в одном месте, платформенном слое, и эта глава — как он устроен: брендово-нейтральный интерфейс, путь декодирования кадров CAN в CarStateView, путь кодирования запроса момента в валидный кадр HCA_01 и супервизор панды, решающий, разрешено ли этому кадру вообще уйти.

Правило проектирования — одно предложение: бренд это одна реализация интерфейса, а не архитектура. Добавление Toyota TSS2 однажды не изменило ни строки в Planner или Control. Дальше — почему так.

Интерфейс#

platform::CarPlatform (include/adas/platform/car_platform.h) — чисто виртуальный класс с четырьмя группами методов, и его форма и есть весь контракт:

чтение шины      isAllowedRxAddress · update(frames) · carState · stateView
запись шины      apply(CarControl) → frames · setCruiseIntent · steerLimits
что разрешено    configureSafety · safetyTick · ignition · safetyModelOk · lateralActuationAllowed
жизненный цикл   init · dbcAssetName · defaults · resetPandaState

Planner и Control видят только stateView() — CarStateView, брендово-нейтральный: скорость, угол руля, скорость рыска, держит ли водитель руль, включён ли штатный круиз. Ни адреса CAN, ни имени сигнала они не видят. VolkswagenMqb (vw_platform.cpp) — единственная реализация, которую выбирает ключ конфига vehicle.name; сервис платформы держит unique_ptr<CarPlatform> и зовёт интерфейс, ничего брендового.

Декод: из кадров в CarStateView#

Входящие кадры сперва проходят один дешёвый гейт — isAllowedRxAddress отбрасывает всё, чего нет в приёмном списке машины, до всякого декодирования, так что занятая шина ничего не стоит на нерелевантном кадре. Что уцелело, идёт в MqbCarStateDecoder, switch по адресу (mqb_car_state_decoder.cpp):

Значения извлекаются не рукописной битовой математикой, а парсером DBC (utils/can_parser.h): extractSignal(frame, "LWI_Lenkradwinkel") возвращает физическое значение по тому же vw_mqb_2010.dbc, что поставляет comma. У этого выбора есть тонкое свойство безопасности, и парсер делает его явным — одна битая строка DBC пропускается, а не фатальна:

# The parser's contract, in miniature: a bad line must not void the whole database.
def load_dbc(lines):
    signals, skipped = {}, 0
    for ln in lines:
        try:
            name, start, length, scale = parse_dbc_line(ln)   # raises on a malformed line
            signals[name] = (start, length, scale)
        except ValueError:
            skipped += 1
    return signals, skipped

def parse_dbc_line(ln):
    # a real SG_ line: "SG_ LWI_Lenkradwinkel : 0|13@1+ (0.1,0) ..."
    if not ln.strip().startswith("SG_"):
        raise ValueError("not a signal line")
    name = ln.split()[1]
    return name, 0, 13, 0.1

sig, skipped = load_dbc(["SG_ LWI_Lenkradwinkel : 0|13@1+ (0.1,0)",
                         "GARBAGE that will not parse",
                         "SG_ ESP_Gierrate : 0|14@1+ (0.01,0)"])
print(f"loaded {len(sig)} signals, skipped {skipped} bad line(s)")

Почему это важно: DBC, не загрузившийся целиком, оставляет машину недекодированной, что снаружи выглядит ровно как машина, которая молчит, — неверный вывод из-за разницы в пробелах в одном не относящемся к делу сообщении. update() возвращает true, когда любое декодированное значение изменилось, и сервис платформы публикует vehicle/state по этому.

Кодирование: сборка легального HCA_01#

apply(CarControl) превращает брендово-нейтральный запрос (момент в cNm, поперечное активно, HUD-биты линий) в кадры, которые примет EPS этой машины. Для руления это HCA_01 по адресу 0x126, и три вещи о нём не обсуждаются — все три принадлежат бренду, потому и живут здесь, а не в Control:

  • величина и знак разделены: 14-битное поле несёт |момент|, отдельный бит несёт знак. Момент зажат в ±STEER_MAX (300) до упаковки.

  • 4-битный катящийся счётчик растёт каждый кадр; EPS отвергает кадр, чей счётчик не сдвинулся.

  • контрольная сумма CRC-8 по полезной нагрузке, полином VW «8H2F» 0x2F, инициализация 0xFF, финальный XOR 0xFF — затем XOR с посчётчиковым секретным байтом. Для HCA_01 этот секрет — константа 0xDA (у GRA_ACC_01, кадра кнопок круиза, он действительно меняется по счётчику); ошибись в секрете — и каждый кадр молча отбрасывается EPS.

def crc8_2f(data):
    """VW MQB 8H2F CRC over bytes 1.. : poly 0x2F, init 0xFF, final XOR 0xFF, plus a counter secret."""
    HCA_SECRET = [0xDA] * 16                       # HCA_01's secret is a constant 0xDA (GRA_ACC_01's varies)
    crc = 0xFF
    for b in data[1:]:
        crc ^= b
        for _ in range(8):
            crc = ((crc << 1) ^ 0x2F) & 0xFF if crc & 0x80 else (crc << 1) & 0xFF
    crc ^= HCA_SECRET[data[1] & 0x0F]              # constant here, so counter-independent
    for _ in range(8):
        crc = ((crc << 1) ^ 0x2F) & 0xFF if crc & 0x80 else (crc << 1) & 0xFF
    return crc ^ 0xFF

def build_hca(torque_cnm, lkas_on, counter):
    torque = max(-300, min(300, torque_cnm))
    d = bytearray(8)
    d[1] = ((counter & 0x0F) << 0) | (0x3 << 4)   # counter in low nibble, a constant in the high
    mag = abs(torque)
    d[2] = mag & 0xFF
    d[3] = ((mag >> 8) & 0x3F) | (0x40 if lkas_on else 0) | (0x80 if torque < 0 else 0)
    d[0] = crc8_2f(d)                              # checksum goes in byte 0, last
    return d

f0 = build_hca(120, True, 3)
f1 = build_hca(120, True, 4)
print("counter 3:", f0.hex(), " counter 4:", f1.hex())
assert f0[0] != f1[0], "same magnitude, different counter → different checksum"
print("checksum changed because the counter sits in the CRC payload — not because of the secret,")
print("which is constant for HCA_01. A wrong or wrongly-varying secret (GRA_ACC_01) drops every frame.")

LDW_02 (приборный HUD разметки) и GRA_ACC_01 (кнопки круиза, свой секрет) строятся так же. У кнопочного кадра есть тонкость, которую стоит знать: нажатие держится, пока штатный счётчик не сдвинется, потому что так эта шина подтверждает кнопку — отпустишь раньше, нажатие не увидят; позже — оно повторится.

Разрешено: супервизор панды#

Даже верно собранный кадр не должен уходить, пока машина не заведена и панда не в нужном режиме безопасности. Этим владеет PandaSafetySupervisor (panda_safety_supervisor.cpp), и он намеренно слоем ниже кодирования — платформа строит кадры каждый тик, супервизор решает, пропустит ли их плата:

  • модель безопасности должна быть kVolkswagen (15); иначе safetyModelOk() ложно и момент не шлётся — неверный режим считается неисправностью, а не обходится;

  • биты альтернативного поведения (например, не-отключаться-по-газу) выставляются на плате при init;

  • зажигание дебаунсится с гистерезисом по напряжению, чтобы просадка не переключала включение;

  • heartbeat шлётся каждый тик супервизора, иначе панда уходит в собственный безопасный режим.

Это же делает панду переживающей сон телефона. Когда заново открытый USB-дескриптор пересаживается в работающий нативный слой, resetPandaState() забывает состояние платы — модель безопасности и alt-exp живут на плате и должны быть выставлены заново, — сохраняя декодированное состояние машины и защёлку круиза. Две неудачные пересадки подряд эскалируют до полного перезапуска; одна невидима контроллерам.

Темпы, и где всё это работает#

Сервис платформы (services/platform.cpp) крутит три таймера: rx и tx по 10 мс, state по 100 мс. rx вычерпывает панду и декодирует; tx строит и шлёт кадры из apply(); state публикует vehicle/state, а рядом едет тик супервизора, публикуя panda/health. Всё выше в этой главе зовётся из этих трёх колбэков и ниоткуда больше — это и позволяет реплею бега и pyadas гонять идентичные декод/кодирование без подключённой панды.

Приёмка#

  • миниатюра DBC грузит хорошие сигналы и считает битую строку, а не падает;

  • сборщик HCA даёт разную контрольную сумму при двух счётчиках — и вы можете сказать почему: счётчик входит в полезную нагрузку CRC, тогда как сам секрет для HCA_01 — константа и меняется только у GRA_ACC_01;

  • по одному предложению: почему stateView() брендово-нейтрален и почему resetPandaState() забывает состояние платы, но хранит состояние машины.
