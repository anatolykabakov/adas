# Разбор заезда

Один вход в данные заезда, поверх кэша. Написано 2026-08-09, когда стало ясно, что находки берутся
не из отдельных разборов, а из их сопоставления — и что сопоставление не делается, если каждое число
стоит минуты ожидания.

## Быстрый путь

```bash
cd app/src/main/scripts
python3 bag_report.py ../../../../adas_logs/2026_08_08_23_00_28
```

Первый прогон по заезду — около 95 секунд, дальше **0.3 секунды**. Разделы выбираются:

```bash
python3 bag_report.py <bag> --only step,torque          # только поперечное
python3 bag_report.py <bagA> <bagB> --only step         # сравнение заездов колонками
python3 bag_report.py <bag> --refresh                   # пересобрать кэш принудительно
```

## Что печатается

| раздел | вопрос, на который отвечает |
|---|---|
| `rate` | темп зрения и время инференса — размер шага уставки задаётся интервалом кадров |
| `step` | шаг уставки и ошибка слежения по радиусу дуги; доля шагов выше упора ПИД (1.67°) |
| `torque` | где момент упирается в потолок панды 300 cNm, и какое при этом поперечное ускорение |
| `lanes` | уверенность модели в своих линиях против статусов управления |
| `pose` | продольная скорость и рыскание из позы модели против шины |
| `notes` | голосовые пометки водителя с числами на тех же секундах |

Раздел `torque` печатает поперечное ускорение рядом с долей упора не для полноты: если момент в
упоре, а ускорение 0.6 м/с², значит он расходуется не на удержание машины в дуге, а на проворот
руля, и лечится это упреждением, а не потолком. Именно так нашлась причина «недокрута».

## Кэш

`vis/bag_cache.py` держит плоские numpy-таблицы в `<bag>/.bagcache_v<N>.npz`, 5–7 МБ на заезд против
800 МБ самого заезда.

**Что не кэшируется: `model_out`** — сырой выход модели, 6504 float на кадр. Он и есть 37 секунд из
55 при разборе `vision/lanes`, а нужен одному разбору из десяти. Кому нужен, идёт в исходные
сообщения через `vis/bag_io.py`.

**Инвалидация по содержимому**: список всех `.bin` с размерами и временем правки плюс версия схемы.
Дописали заезд или поменяли набор столбцов — кэш пересобирается сам. Проверено: правка одного файла
роняет кэш, следующий прогон снова мгновенный. Молчаливо устаревший кэш хуже отсутствующего, потому
что выглядит как свежий результат.

Меняете `_build` — **поднимайте `SCHEMA_VERSION`**. Иначе старый кэш ответит новым именем поля.

## Голос

Звук пишется вместе с багом как `audio_<t>.m4a`, где t — момент старта по тому же монотонному
счётчику, что и метки всех сообщений. Значит `метка_в_баге = t + позиция_в_файле_мс`, без пересчёта
часов.

```bash
python3 bag_voice_notes.py <bag> --model medium        # первый раз: десятки минут
python3 bag_report.py <bag> --only notes               # дальше из кэша транскрипта
```

Ключевое слово по умолчанию «запиши» — оно отделяет пометку от разговора и радио. Транскрипт
кэшируется рядом со звуком, поэтому менять разбор (другое слово, другая склейка) можно бесплатно.

**VAD выключен намеренно.** С ним на заезде 2026_08_08_23_00_28 оставалось ДВА сегмента на 22 минуты
и разнесённые пометки склеивались в одну: речь в машине тише дорожного шума, детектор считает её
тишиной. Без VAD дороже по времени, зато ничего не теряется.

Запись идёт с `AudioSource.MIC`, то есть с сырого микрофона: он сохраняет сигнал, удар, скрип — при
разборе инцидента это улика. `VOICE_RECOGNITION` вытянул бы речь лучше, но подавил бы ровно эти
звуки. Размен, а не улучшение.

## Отдельные разборы, которые в сводку не входят

| скрипт | почему отдельно |
|---|---|
| `bag_arc_offset.py` | раскладывает смещение на слежение и опору, а опору — на план, разметку и сдвиг; тяжёлый и с своими ключами |
| `bag_feedforward_ab.py` | воспроизводит внутренний контур с другими гейнами; **разомкнуто**, читать как верхнюю границу |
| `bag_controller_ab.py` | гоняет настоящий C++ `LaneKeepService` через `pyadas` для сравнения pp/mpc/fp |
| `latency.py` | подробная разбивка задержек по этапам конвейера |

Первые два уже ходят через кэш.

## Чего эти числа не доказывают

`bag_feedforward_ab.py` разомкнут: записанный фактический угол руля получен под теми гейнами,
которые тогда стояли. С другими момент был бы другим, машина повернула бы иначе, и ошибка была бы
иной. Замкнуть контур офлайн нечем — нужна проверенная модель реакции рейки, а её нет. Поэтому
изменения в контуре управления проверяются заездом, и критерий пишется заранее, в
[`PREDRIVE.md`](PREDRIVE.md).
