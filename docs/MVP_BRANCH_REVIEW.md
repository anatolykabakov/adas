## Вердикт

Ветка — большой монолитный завоз продукта поверх пустого `main`, плюс один содержательный follow-up по поперечному контуру и runtime-ручкам. По направлению это осмысленный MVP (LKA + safety/long path, Panda/MQB, офлайн-анализ).
К merge в «чистый» main как к одному PR — тяжело: огромный diff, смешанные concerns (код + книга + картинки + gradle wrapper), слабая атомарность истории.

**Рекомендация:** не squash’ить всё в один «mvp» без разбора; для следующих изменений — резать по темам. Критичные замечания по CI и сообщениям коммита — ниже.

## Коммит `1ef242c` — `mvp`

### Что сделано хорошо

- Полный каркас: Java (камера/ONNX/UI) + C++ сервисы + `Middleware` pub/sub/timers + Panda/MQB + bag/sim/scripts.
- Есть unit-тесты middleware, lane keep, panda/safety — не только «код без проверки».
- Документация и book закрывают контекст для команды, не только для автора.

### Проблемы

1. **Атомарность истории**
   Один коммит с пустым телом и названием `mvp` на десятки тысяч строк. Невозможно bisect’ить регрессии (руление, health, middleware). Для такого объёма нужны были серии: middleware → panda → lane keep → android → scripts/docs.

2. **Смешение артефактов**
   В том же коммите: исходники, `gradle-wrapper.jar`, DBC, png/svg книги, chessboard. Wrapper/бинари обычно ок для Android-репо, но book-assets раздувают diff без нужды для сборки APK.

3. **Сообщение коммита**
   Пустое тело — нет «зачем / что критично / как проверить».

## Коммит `c6304dd` — runtime params + lateral/path

### Что сделано хорошо

- **Live-параметры** в middleware (`ParamBag`: queue на чужом потоке, flush на потоке сервиса) — убирает зоопарк `nativeSet*`.
- **Lane age gate** — закрывает дыру, когда vision встаёт, а HCA продолжает жить за счёт быстрого PID по углу.
- **Panda health v11** — явный разбор прошивки comma-two; без этого зажигание/safety читаются из чужих байт.
- **Path fusion:** blend/σ/ширина/offset, `center_force` выключен по измерению — осознанный trade-off, не «забыли включить».
- Расширение debug в bag + офлайн-скрипты (`bag_arc_offset`, calib) — хорошая связка road → analysis.
- Тесты на params, stale-gate, health v11, path fusion.

### Проблемы и риски

1. **~~Сообщение коммита устарело относительно кода~~** — исправлено: из message убраны its middleware / `parameter_storage`.

2. **CI APK: Java 17 vs project Java 21** *(high)*
   `.github/workflows/ci.yml` ставит Temurin 17, а `app/build.gradle` — `VERSION_21`. Job APK, скорее всего, не соберёт приложение, которым реально рулят.

3. **CI controller: падения sim не валят job** *(high)*
   Скрипт прогона `sim.eval` без `set -e`; шаг заканчивается `cp` артефактов. Не-zero от порогов теряется — регрессии поперечки в CI молчат.

4. **`center_force_gain: 0.0` в shipped `config.json`** *(medium / intentional?)*
   Документы и README местами ещё намекают на 0.4 как рабочее значение; в конфиге член выключен (и это обосновано VS dragonpilot / темпом контура). Ок, если везде явно «OFF until faster loop»; иначе расхождение docs ↔ APK.

5. **Качество истории / шум от массовых правок**
   В том же коммите: перевод доков на EN, чистка комментариев, правки скриптов. Ревьюеру сложно отделить «поведение машины» от «косметики». Риск: в косметике уже ловили порчу литералов (`1'000'000` → `11'000'000`, `50'000` → `5050'000`) — сейчас в HEAD починено, но это сигнал, что огромные AI-правки без узкого diff опасны.

6. **~~Жёсткий путь к карте OSM в скриптах~~** — исправлено: `DEFAULT_MAP` от корня репо (`maps/Moscow.osm.admap`), как в `fetch_map.py`.
