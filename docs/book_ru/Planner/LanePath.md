# Путь разметки — из двух линий и плана в одну опору

Планировщик рулит не на линии разметки и не на план вождения модели. Он рулит на **одну** полилинию в
`vision/path`, а она — слияние того и другого, которое пересчитывается каждый кадр зрения в
`laneLinesToPath` (`utils/lane_path.cpp`, питоновское зеркало — `core/path_fusion.py`). Эта глава — про
само слияние: что на входе, как назначается вес и от каких двух отказов оно спасает. Это последний шаг
перед [контроллерами](./MPC_and_FP.md), и здесь решается примерно половина измеренного смещения от центра.

## Два источника, и почему ни одного не хватает

| источник | откуда | сила | режим отказа |
|---|---|---|---|
| **линии разметки** | `lanes[1]` (ближняя левая), `lanes[2]` (ближняя правая) | геометрический центр *именно этой* полосы | одна пропадает; σ разлетается на дугах и в дождь |
| **план модели** | `plan_x` / `plan_y`, собственный путь сети | есть всегда, всегда гладкий | **срезает внутрь** дуги — систематическое смещение уставки |

Линии верны, пока есть, и врут, как только пропадают. План есть всегда, но на дугах всегда чуть неверен.
Слияние — не подстраховка «на всякий случай», а способ брать каждый источник ровно там, где отказывает другой.

## Как читаются линии: что значит «ближняя левая»

Supercombo выдаёт четыре линии; стек берёт две линии своей полосы, `lanes[1]` и `lanes[2]`, на той же
продольной сетке, что и план (`lanes(1).y_size() == nx` — проверка-страж в `lane_path.cpp`: линию на
другой сетке считают отсутствующей, а не пересэмплируют). Каждая линия несёт вероятность и поточечное
стандартное отклонение; слияние сжимает всю кривую σ до одного числа — медианы по ближнему полю, ведь
именно в этом диапазоне и работает контроллер.

```python
import numpy as np

def line_std(y_std, x, lo=5.0, hi=40.0):
    """One confidence number per line: median σ over the range the controller uses."""
    sel = (x >= lo) & (x <= hi)
    return float(np.median(y_std[sel])) if sel.any() else float("nan")

x = np.arange(0.0, 60.0, 2.0)
sigma_near = 0.05 + 0.01 * x          # grows with range, as real lane σ does
print(f"median σ over 5-40 m: {line_std(sigma_near, x):.2f} m")
```

## Два гейта и вес

Линия попадает в опору, пройдя два независимых теста, а затем входит с некоторым весом:

1. **вероятность**, смягчённая, чтобы линия чуть выше порога не выскакивала сразу на полный вес:

```python
def soft_prob(p, min_p=0.3):
    if p < min_p:
        return 0.0
    return min(1.0, (p - min_p) / max(1e-3, 1.0 - min_p))
```

2. **σ-уверенность** — полный вес до `lane_std_good_m` (0.15 м) и линейный спад до нуля к `lane_std_bad_m`
   (0.30 м). Это собственные полосы `laneLineStds` от comma: ниже 0.15 м модель уверена настолько,
   насколько вообще способна, а выше 0.30 м — по сути гадает:

```python
def std_conf(median_std, good=0.15, bad=0.30):
    if median_std < 0:
        return 1.0
    if median_std <= good:
        return 1.0
    if median_std >= bad:
        return 0.0
    return (bad - median_std) / (bad - good)
```

3. **ширина** — паре доверяют (она *заякорена*) только если обе линии прошли и их медианная разница лежит
   в пределах [2.6, 4.6] м. Стык гудрона или полоса слияния обычно нарушают ширину, так что одна дешёвая
   проверка отсекает самый частый случай «уверенно, но неверно».

## Слияние и единственная важная ручка

Когда пара заякорена, центр полосы — это взвешенная по вероятности середина двух линий (каждая сдвинута
внутрь на половину измеренной ширины), а вес подмешивания — «мягкое ИЛИ» двух вероятностей в духе
flowpilot, масштабированное на `path_lane_blend_scale`:

$$
d_{\mathrm{prob}} = (p_L + p_R - p_L p_R)\cdot \mathrm{path\_lane\_blend\_scale}
$$

$$
y = d_{\mathrm{prob}}\,y_{\mathrm{lane}} + (1-d_{\mathrm{prob}})\,y_{\mathrm{plan}}.
$$

```python
def blend_reference(x, y_plan, y_L, y_R, p_L, p_R,
                    std_L=0.1, std_R=0.1, blend_scale=0.6,
                    w_min=2.6, w_max=4.6):
    """Fuse lines and plan into one y(x). Device frame, y right-positive."""
    p_L = soft_prob(p_L) * std_conf(std_L)
    p_R = soft_prob(p_R) * std_conf(std_R)
    sel = (x >= 5.0) & (x <= 40.0)
    w_med = float(np.mean(np.abs(y_R[sel] - y_L[sel]))) if sel.any() else 0.0
    anchored = (w_min < w_med < w_max) and p_L > 0 and p_R > 0
    d_prob = (p_L + p_R - p_L * p_R) * blend_scale if anchored else 0.0

    w = np.clip(np.abs(y_L - y_R), w_min, w_max)
    y_lane = (p_L * (y_L + 0.5 * w) + p_R * (y_R - 0.5 * w)) / (p_L + p_R + 1e-6)
    return d_prob * y_lane + (1.0 - d_prob) * y_plan, d_prob, anchored

# The plan cuts 40 cm inside by 40 m; the paint is centred.
x = np.linspace(0, 40, 21)
y_plan = -0.40 * (x / 40.0)
y_L, y_R = -1.75 * np.ones_like(x), 1.75 * np.ones_like(x)
for scale in (0.0, 0.6, 1.0):
    y, d, ok = blend_reference(x, y_plan, y_L, y_R, 0.95, 0.95, blend_scale=scale)
    print(f"blend={scale:.1f} anchored={ok} d_prob={d:.2f}  y(40)={y[-1]:+.3f} m")
```

`blend=0` едет по срезающему плану вплоть до −0.40 м; `blend=1` сидит на центрированной разметке; боевые
**0.6** оставляют 40 % внутренней срезки плана даже при идеальных линиях. Так и задумано: comma-two
полностью доверяет разметке при `d_prob≈1`, но на этом телефоне линии редко бывают настолько хороши,
поэтому частичное подмешивание — честный компромисс.

## Почему смещение живёт именно здесь

Два измеренных факта делают эту главу важнее, чем можно подумать по её объёму. В заезде 2026-08-21
медианная σ была 0.37 м слева и 0.51 м справа — **обе** уже за краем нулевого веса 0.30 м, — и обе линии
проходили гейты одновременно лишь в ~22 % кадров. Значит, большую часть времени `d_prob` схлопывается в
ноль, и опорой *служит* план со всей его внутренней срезкой. Именно это σ-вето и винят примерно в половине
смещения от центра на дугах (открытая задача #39); поднимать `path_lane_blend_scale` бесполезно, пока σ в
плохой зоне, — вес всё равно нулевой.

```python
for sig in (0.12, 0.20, 0.37, 0.55):
    _, d, _ = blend_reference(x, y_plan, y_L, y_R, 0.95, 0.95,
                              std_L=sig, std_R=sig, blend_scale=0.6)
    print(f"σ={sig:.2f} m → d_prob={d:.2f}  ({'lines help' if d > 0.05 else 'plan only'})")
```

После слияния добавляется один постоянный сдвиг — `path_camera_offset_m` (0.05 м), поправка на то, что
камера стоит не на осевой линии. На прямых остаточное смещение — 3.6 см; на дугах оно на порядок больше, и
это срезка плана, проступающая сквозь схлопнувшееся подмешивание, а не ошибка калибровки.

## Приёмка

* перебор подмешивания воспроизводится: `blend=0` едет по плану, `blend=1` — по разметке, `blend=0.6` —
  между ними;
* перебор σ показывает, как `d_prob` падает в ноль, едва σ переваливает за 0.30 м, — так что, зная 0.37 и
  0.51 м из заезда, вы можете объяснить, почему линии обычно не участвуют;
* одно предложение, связывающее долю «обе уверены» ~22 % со смещением на дуге.
