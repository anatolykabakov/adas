# GPS — локальные метры, что он даёт и как сделать, чтобы коррекция дожила

Одометрия уплывает; единственная абсолютная опора у телефона — его GPS. Эта глава переводит широту и долготу в
метры на локальной плоскости, честно смотрит, что фикс в 1–5 м может и не может поправить, и разбирается,
почему коррекция, дошедшая до фильтра, через секунду всё равно может исчезнуть.

## Шаг 3a: GPS → локальные метры


Начало $(\phi_0,\lambda_0)$ — первый валидный фикс. С радиусом Земли $R = 6\,371\,000$ м:

$$
\begin{aligned}
\Delta\phi &= (\phi-\phi_0)\tfrac{\pi}{180},&
\Delta\lambda &= (\lambda-\lambda_0)\tfrac{\pi}{180},\\
y &= R\,\Delta\phi && \text{(север)},\\
x &= R\,\Delta\lambda\cos\phi_0 && \text{(восток)}.
\end{aligned}
$$

Пеленг (градусы от севера по часовой) → рыск в ENU (от востока против часовой):

$$
\psi = \mathrm{normalize}\Big(\tfrac{\pi}{2} - b_{\deg}\tfrac{\pi}{180}\Big).
$$

Это $\tfrac{\pi}{2} - b$ стоит выжечь в памяти. Однажды перевёрнутое, оно дало в анализе заезда сообщение об
ошибке курса в 103° там, где настоящая ошибка была 0.3°, и час ушёл на охоту за несуществующей ошибкой
фильтра.

Курсу доверяют только выше $v > 2$ м/с, а особенность стояния ($v < 0.5$ при почти нулевом пеленге)
отбрасывается. Затем $v_x = v\sin b$, $v_y = v\cos b$.

```python
import math

R_EARTH = 6_371_000.0

def enu_from_ll(lat_deg, lon_deg, lat0_deg, lon0_deg):
    dlat = math.radians(lat_deg - lat0_deg)
    dlon = math.radians(lon_deg - lon0_deg)
    y = dlat * R_EARTH                                       # North
    x = dlon * math.cos(math.radians(lat0_deg)) * R_EARTH     # East
    return x, y

def yaw_enu_from_bearing_deg(bearing_deg):
    return (math.pi / 2 - math.radians(bearing_deg) + math.pi) % (2 * math.pi) - math.pi

print(enu_from_ll(55.001, 37.001, 55.0, 37.0))   # ~(64 m East, 111 m North) at φ₀=55°
for b in (0.0, 90.0, 180.0, 270.0):
    print(f"bearing {b:5.0f}° → ENU yaw {math.degrees(yaw_enu_from_bearing_deg(b)):+7.1f}°")
```

Плоская Земля подходит для заезда на несколько километров. Пересечение сброса начала координат (перезапуск
приложения) начинает **новую** плоскость — не сшивайте беги без повторной привязки.

## Шаг 3b: что даёт GPS и что он прячет


Измерено против GNSS на ночном заезде (23.5 мин, трёхмерный фикс всё время):

| величина | согласие |
|---|---|
| курс против курса GNSS | 0.3° медианно, 5.4° p99 |
| скорость против GNSS | 0.17 м/с медианно |

Выглядит отлично, и так оно и есть — с оговоркой, что число по курсу частично измеряет, как часто GPS
защёлкивал курс на место, а число по скорости несёт описанное выше смещение радиуса колеса. Фильтр,
сравниваемый с тем, что его корректирует, всегда будет выглядеть хорошо.

Честная проверка фильтра — что он делает, когда источника нет. Ровно для этого нужна симуляция дуги выше, и
именно поэтому правка со скоростью рыска была важна, хотя ни один записанный заезд не жаловался.

## Шаг 4: как сделать, чтобы коррекция дожила, и обнаружить, что этого всё равно мало

Шаг 3 дал ограниченные позицию и курс. Он не дал заслуживающей доверия **скорости**, и причина той же формы,
что в шаге 2, — это стоит увидеть дважды, потому что так фильтр Калмана тихо выводят из строя чаще всего.

`updateGpsVel` вызывался. Но `predict` делал `state_(3) = v_measured` на каждом тике, то есть примерно каждые
10 мс, а скорость GPS приходит раз в 0.2 с. Значит коррекцию перезаписывало около двадцати раз до прихода
следующей. Слитая скорость была скоростью колёс с точностью до шестого знака.

Была и вторая, независимая причина: обновлению задали `R = 1.0`, то есть предположенный шум доплера в 1 м/с.
Измеренный доплер на порядок лучше — остаток против скорости колёс с исправленным масштабом составляет
0.066–0.101 м/с, и в него входят оба датчика плюс дискретизация 1 Гц.

Две причины взаимодействуют так, что стоит предсказать до запуска кода. В старом режиме с присваиванием
дисперсию скорости ничто не сжимало, поэтому она росла без границы и усиление GPS подходило к единице:
обновление сдвигало скорость *полностью* к значению GPS, а следующий тик это выбрасывал. Сделайте скорость
состоянием — и дисперсия теперь мала, поэтому при `R = 1.0` обновление почти не регистрируется. Только с
обеими правками оно и попадает, и держится.

Обе исправлены: скорость — состояние (`setSpeedIsAState`), а `gps_vel_R` равно $0.1^2$.

```python
# The two failure modes and the fix, in one experiment. True speed 20.0; CAN reports 20.24 (the measured
# 1.2 % scale); GPS velocity reports the truth once every 20 ticks.
class SpeedState:
    """The speed part of the EKF, with the old behaviour available for comparison."""

    def __init__(self, as_state=True, q=0.5**2, r_wheel=0.1**2):
        self.as_state, self.q, self.r_wheel = as_state, q, r_wheel
        self.v, self.p = 20.0, 1.0

    def predict(self, v_wheel):
        if not self.as_state:
            self.v = v_wheel                      # <-- the assignment that erased everything
            self.p += self.q
            return
        self.p += self.q
        k = self.p / (self.p + self.r_wheel)       # wheel speed as a measurement
        self.v += k * (v_wheel - self.v)
        self.p *= 1 - k

    def observe_gps(self, v_gps, r_gps):
        k = self.p / (self.p + r_gps)
        self.v += k * (v_gps - self.v)
        self.p *= 1 - k


def run(as_state, r_gps, ticks=400, every=20):
    f = SpeedState(as_state=as_state)
    right_after = None
    for i in range(ticks):
        f.predict(20.24)
        if i % every == 0:
            f.observe_gps(20.0, r_gps)
            right_after = f.v
    return right_after, f.v

for label, as_state, r_gps in (("assigned, R=1.0  (as shipped before)", False, 1.0),
                               ("state,    R=1.0  (noise still assumed)", True, 1.0),
                               ("state,    R=0.01 (Doppler as measured)", True, 0.1**2)):
    after, end = run(as_state, r_gps)
    print(f"{label}: right after GPS {after:.4f}, one GPS period later {end:.4f}")
```

Прочитайте третью строку внимательно. Коррекция теперь попадает — и к моменту, когда GPS заговорит снова,
скорость колёс затянула оценку обратно к 20.24.

Это не провал настройки, а неидентифицируемость. Смещённое измерение приходит в двадцать раз чаще при том же
предполагаемом шуме, поэтому между посылками выигрывает оно; и никакая пара предположений о несмещённом шуме
не отделит **постоянное смещение на частом измерении** от истины. Понизить доверие к колёсам значило бы
выбросить их по-настоящему низкий шум и ухудшить оценку везде.

Выход — перестать делать вид, что смещение это шум, и дать ему собственное состояние: оценивать масштаб. Именно
это `paramsd` делает для параметров машины, и поэтому шаг 5 — то место, где эта глава останавливается, а та
работа начинается.

```{admonition} Общий урок
:class: tip
Дважды в одном фильтре измерение победила не плохая математика, а присваивание в шаге предсказания. Если вам
досталcя оценщик и датчик «как будто ни на что не влияет», сначала проверьте, не пишет ли кто-то ниже по
потоку в его состояние.
```
